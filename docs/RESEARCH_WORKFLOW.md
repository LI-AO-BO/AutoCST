# 在对话中做可追溯仿真

AutoCST v0.2 把实验约定、单次运行、结果事件分别保存。Codex 负责理解研究想法、写清假设、解释结果和选择下一轮；独立执行器负责已提交的建模、求解、保存与确定性指标计算。用户明确授权自动优化批次后，执行器也可依据冻结算法和反馈，在约定范围内选择下一组参数。

## 开始一个研究想法

先确定要验证什么、需要观察什么、什么结果会反驳假设。实验约定 `spec` 包含目标与容差、约束、固定模型参数、允许调整的参数范围，以及最大运行次数、总求解时间、单次求解时间。

使用 `cst_create_experiment` 保存约定，得到 `experiment_id`。准备前查询手册或本机同版本帮助，不能仅凭模型记忆猜测 CST 命令。当前模板是矩形波导和周期反射单元；其他高频结构使用显式历史脚本，或复制已有 `.cst` 后操作复制品。自定义结构的结果树和指标必须明确，不能套用波导的正确性检查。

`cst_prepare_simulation` 只验证与保存可查看的输入，返回脚本文件、参数、选定 CST 实例身份和 `prepared_id`。每轮 `decision` 至少记录：本轮假设、上一轮证据、改变的参数、预期结果、可能的反证。这里记录可审核的研究决策摘要，不记录模型内部思维过程。

在用户已授权的参数和预算内，检查准备内容后直接调用 `cst_submit_prepared`。相同提交必须复用同一 `idempotency_key`，防止断线后重复运行。模板、拓扑、目标或预算变化应先取得用户授权，再使用 `cst_revise_experiment` 新建约定版本；已提交运行保留原版本。

## 结果驱动下一轮

正常求解由独立工作进程调用官方 `Model3D.run_solver(timeout=None)`。该调用在求解和后处理结束后返回；Runner 等待工作进程的 Windows 原生退出信号，核对成功收据后立即保存、导出和分析，再发出该运行专属的命名完成事件。正常等待期间没有按固定间隔查询 CST 状态，相关接口依据见[官方证据](official-evidence.md)。

Runner 每 10 秒更新健康记录，并检查数据库中漏发通知的队列、控制请求或完成记录。这是后台存活与持久通知的兜底，不查询 CST，也不决定正常求解何时完成。同步工作进程丢失后的异常恢复可由 CST 工程目录变化触发有界状态核查；这种恢复核查与正常路径分别记录。

1. 当前对话可保持 Windows 完成事件等待，收到信号后再读结果；`integration/verify_research_simulation.py --wait` 提供此入口。`cst_research_run_status` 用于查看当前阶段，`cst_completion_events` 用于读取持久化完成或故障记录，不需要反复定时查询。观察超时只结束等待，不取消或重试求解。
2. 完成后用 `cst_research_run_results` 读取原始数据、指标与限制，再用 `cst_experiment_context` 查看已试参数、最佳候选、剩余预算和建议。
3. 分别说明：求解是否成功、数据是否完整、数值一致性是否通过、网格/模式是否收敛、目标是否达到。单网格命中只算候选，物理实测独立记录。
4. 比较预测和观察；在范围内提出下一组参数，记录依据并准备下一轮。确定性粗扫/细化建议是参考，不是全局最优证明。不能用没有证据的随机改参数掩盖模型错误。
5. 下一轮提交成功或故障已处理后确认相应事件。保存事件游标，重复读取不能重复提交。

停止条件包括达到经验证的目标、预算耗尽、连续无效结果、用户暂停。`pause` 让当前运行结束但阻止后续开始；`cancel` 是终止当前求解的明确请求，需要 CST 返回停止证据。任何不明确的连接/执行状态进入 `needs_attention`，保留任务占用；`resume` 只重新核实和恢复阶段，不重复启动求解。

## 自动优化批次

用户明确授权批次范围后，调用 `cst_start_optimization`，提交 `experiment_id`、`job_template`、`max_new_runs`、`idempotency_key` 及可选算法配置。当前实现对结构化相位目标使用高斯过程和期望改进，基于已有有效运行提议下一点；每轮先冻结输入、记录决策，再幂等提交。该算法按既定目标搜索，研究假设、模型或目标的新解释仍由 Codex 与用户调整。

一个实验只允许一个未结束批次。同内容、同启动键返回同一个 `batch_id`；使用 `cst_optimization_status` 查看进展，该查询不推进批次。`max_new_runs` 包含优化及复验新增运行，实验原有参数范围、次数和时间预算仍适用，不因批次启动而扩大。

超表面相位候选命中后，如果实验声明了独立初始网格列表和相位/幅度变化容差，批次保持全部物理参数，仅补齐缺少的网格运行。复验结论保存为独立汇总，不改写单轮分析；有限网格稳定性不代表其他模型、模态收敛或硬件实测。未声明复验则以待验证候选结束。

`cst_control_optimization` 的 `pause` 和 `stop` 阻止未来提议，已经提交的运行仍会执行，包括仍在队列中的运行。实验 `pause` 才会阻止已排队运行开始；实验 `cancel` 才明确请求停止当前求解。批次 `resume` 先核对冻结实验版本、实现与来源工程哈希、CST 实例身份。失败、取消或状态不明确的运行不会被自动重新求解；已结束批次不能重启。

批次记录位于 `.autocst/optimization_batches/<batch_id>/`。其中保存冻结模板和策略、每轮提议、预备任务与幂等键检查点、控制与完成通知、复验汇总，并关联各轮 `run_id`。程序在提交成功但收据未保存的恢复窗口复用原检查点与运行键，不重新生成参数或重复求解。

## 对话关闭和恢复

Windows 当前用户的计划任务运行独立执行器，MCP 是可随时关闭的短连接。电脑保持开机、登录；有任务时执行器持有临时防自动睡眠租约，不改变电源计划，也不能阻止主动关机或睡眠。

Codex 关闭时，已经提交的求解、导出和指标计算由执行器继续，结果事件留在本地。已经明确授权的优化批次也可以按冻结算法继续有限调参；下一轮 Codex 推理等应用可用后恢复，没有另外开设收费 API 模型。

当前旧的 15 分钟 Codex 定期唤醒已暂停。Windows 完成信号可唤醒仍在执行的等待调用，但尚未实现经验证的“仿真结束后即时启动已结束的本机聊天新回合”接口。不能把后台完成通知等同于原聊天自动唤醒；详细边界见[完成信号与聊天唤醒](CODEX_EVENT_WAKEUP.md)。

新聊天可从 `.autocst/experiments/<experiment_id>/context.json` 或 `cst_experiment_context` 恢复实验。运行目录 `.autocst/research_runs/<run_id>/` 保留输入、目标版本、决策、模型脚本、CST 工程、求解与连接证据、结果和分析。原始来源和既有结果不覆盖。

恢复时核对 CST PID、进程创建时间、工程绝对路径和输入散列：正在求解则继续监控；已成功则继续导出/分析；导出失败只重试导出。无法确定是否启动过的任务不自动重跑。需要重新计算时使用新 `run_id` 并记录父运行。

## 参数与结果修改日志

每次调参生成新的 `run_id`，保存本轮输入和结果；不会用下一轮的结果替换上一轮。改变实验约定生成新版本，旧运行仍按提交时的版本分析。

| 记录 | 内容 |
| --- | --- |
| `job.json`、`spec.json` | 本轮参数、模型、指定实例、目标与预算的冻结版本 |
| `decision.json` | 假设、上一轮证据、父运行、参数改动及预期观察 |
| `manifest.json`、`history.vba` | 输入哈希与实际建模脚本，用于复核输入是否改变 |
| `api_calls/`、求解收据和 CST 日志 | 建模、求解、导出及异常恢复的执行证据 |
| CSV、`research_result.json`、`analysis.json` | 原始曲线、结构化结果、目标误差、约束与科研有效性判定 |
| SQLite 事件与控制记录 | 阶段变化、完成、故障、暂停、恢复及取消请求 |

可在项目目录运行 `integration/render_research_report.py --root . --experiment-id <experiment_id>` 刷新 `.autocst/experiments/<experiment_id>/report.md` 与 `report.png`。报告列出逐轮参数差异、结果变化、决策和原始证据链接；这是可更新的汇总视图，各运行目录中的原始记录保留。数值复验汇总另外保存，不为了宣布通过而改写单轮分析。

## 当前验收边界

短算例、故障注入和后台健康记录各自提供不同证据。当前 16 小时后台存活与真实超过 12 小时的 CST 求解尚未完成验收。后台存活检查不是长时 CST 仿真，也不证明关闭 Codex、锁屏、注销和重启均可无条件连续求解。真实长作业、关闭应用和锁屏须分别报告实际验收状态，见 [VERIFICATION.md](../VERIFICATION.md)。v0.1 的短波导验收保留为历史记录，不代替 v0.2 的长时和恢复验收。
